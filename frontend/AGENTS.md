## 3. Naming (strict)

| Thing | Rule | Example |
| --- | --- | --- |
| Folders | `kebab-case` | `features/university/` |
| Component / page files | `PascalCase.tsx`, **named export**, one component per file | `StudentDashboardPage.tsx` |
| Pages | `<Area><Screen>Page` | `GuestBrowseOffersPage`, `AuthLoginPage`, `UniversityApplicationDetailPage`, `PlatformCompanyVerificationPage` |
| Hooks | `useXxx.ts` / in `hooks.ts`, camelCase | `useOffersList`, `useApplication(id)` |
| Query hooks | `use` + noun | `useOffer(id)` |
| Mutation hooks | `use` + verb + noun | `useSubmitApplication`, `useCompanyDecision` |
| API functions | `verbResource` | `listOffers`, `getOffer`, `createOffer`, `publishOffer`, `postCompanyDecision` |
| Query keys | factory per feature in `keys.ts` | `offerKeys.list(params)`, `offerKeys.detail(id)` |
| Zod schemas | `xxxSchema`; types `XxxFormValues` | `offerFormSchema`, `OfferFormValues` |
| Props types | `XxxProps` (not exported unless reused) | `StatusPillProps` |
| Event props / handlers | `onXxx` / `handleXxx` | `onSubmit`, `handleRejectClick` |
| Booleans | `is/has/can/should` | `isLoading`, `canApply` |
| Constants | `SCREAMING_SNAKE_CASE` | `PAGE_SIZE`, `MAX_UPLOAD_BYTES` |
| Types / enums-as-unions | `PascalCase`; string unions, **no TS `enum`** | `type Role = 'student' \| …` |
| Route constants | `ROUTES.<area>.<screen>`; param routes are functions | `ROUTES.student.applicationDetail(id)` |
| Strings | per-feature `strings.ts`, `export const S = {…} as const` | `S.dashboard.title` |
| Commits | Conventional Commits, scope `web-<area>` | `feat(web-student): add applications table` |
| Branches | `feat/web-<area>-<topic>` | `feat/web-company-offers-crud` |

**API data is never renamed or camel-cased.** Use generated types as-is (`offer.company_user_id`,
`application.company_reason`). Only your own props/local variables are camelCase.
`Role` = `'student'|'company'|'supervisor'|'university_admin'|'platform_admin'` (exact, lowercase).

## 4. Data-layer rules

- One HTTP entry point: `api/http.ts` → `http<T>(service, path, init)`. `service` ∈
  `identity|offers|applications|internships|notifications`; base `/svc/<service>` (Vite proxy
  in dev, nginx in prod). Adds `Authorization: Bearer`, single-flight 401 → refresh → retry once →
  logout. Never call `fetch` directly except for blob downloads (use `downloadFile()` in `http.ts`).
- Components never call `api/*` directly — only through hooks in the feature's `hooks.ts`.
- TanStack Query for **all** server state; no server data in `useState`/context. Mutations
  invalidate through the feature's key factory.
- Errors: `normalizeError(e): ApiError` (`{status, code?, message, fieldErrors?}`). Render
  `message`/`detail` first, then field errors inline (design-plan §6.10). Toast for success,
  inline for field errors, `ErrorState` for failed page loads, `EmptyState` per table.
- Status vocabularies are separate maps in `lib/status.ts` (`APPLICATION_STATUS`, `OFFER_STATUS`,
  `INTERNSHIP_STATUS`, `SUBMISSION_STATUS`, `CANCELLATION_STATUS`, `VERIFICATION_STATUS`), each
  `Record<apiValue, {label: string; tone: Tone}>`. Never compare strings across services; never
  inline a label.
- Pagination: two shapes (design-plan §4). Always normalise with `lib/pagination.ts`:
  `normalizeDrfPage(res)` / `normalizeOffsetPage(res)` → `Paged<T> = {items: T[]; total: number}`.
- Names are not in the API: resolve via `features/directory` — `useUserLabel(userId, role)`,
  `useCompanyLabel(companyId)`, `useOfferSummary(offerId)`. Fallback `Role · 3f2a9c`
  (`shortId()` in `lib/ids.ts`). Never invent names.
- Dates only through `lib/format.ts`: `formatDate`, `formatDateTime`, `formatRelative`
  (`en-GB`, `Africa/Algiers`, `dd/mm/yyyy`). Never `toLocaleDateString` in components.
- Decimal strings (`grade "17.50"`) are parsed/formatted in one helper `formatGrade()`.
- Downloads: authenticated `fetch` → blob → object URL. Plain `<a href>` will 401.
- `PUT /api/users/me/profile/` is a full replace: load first, submit **all** required fields.

Button({ variant?: 'primary'|'secondary'|'destructive'|'link'; size?: 'md'|'sm'; isLoading?: boolean; ...ButtonHTMLAttributes })

## 7. Definition of done (every screen)

- Route registered in `app/router.tsx` with the path from design-plan §2 and the guard for its role.
- Matches the Figma frame at 1440×900 and does not overflow at 1280.
- Loading skeleton on first load, empty state, error state (all three present).
- Every Δ note for that screen honoured; excluded features (design-plan §5) absent.
- Actions call the exact endpoints in design-plan §3; API errors shown (`message`/`detail`, then fields).
- All user-visible strings in the feature's `strings.ts`.
- `npm run lint && npm run typecheck && npm run test` green; no `console.log`, no `any`, no unused code.
- Screenshot of the finished screen next to the Figma frame attached to the PR.

## 8. Working agreement

- Small PRs (≤ ~400 changed lines), one screen or one component group each. Rebase on `main` before
  opening. The other person reviews within 2 hours; if CI is green and you touched **only your own
  paths**, you may self-merge after that window. Shared files (`app/router.tsx`, `app/nav.ts`,
  `app/routes.ts`, `tailwind.config.ts`, `lib/*`, `api/http.ts`): keep edits tiny and message first.
- `api/schema/*` regenerated only by Person A when `contracts/` changes.
- Blocked by the other person's component? Build against the frozen API in §6 with a local
  throw-away stub **outside** `src/`, never commit the stub.
- Never rewrite or reformat files you do not own. No drive-by refactors.
- When in doubt about a behaviour: read design-plan §3 for that screen, then the contract, then ask.
